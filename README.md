# habrdigest

Телеграм-бот, который следит за новыми статьями на Хабре по выбранным темам, сокращает их через YandexGPT и присылает дайджест подписчикам.

## Задача

Лента Хабра за день — это десятки статей, из которых интересны единицы. Читать заголовки вручную дорого, RSS не отсеивает лишнее и не даёт понять, о чём статья, без перехода по ссылке.

Бот берёт это на себя: подписываешься на темы, раз в несколько часов он забирает свежие статьи, прогоняет каждую через модель и присылает выжимку. Решение читать или нет принимается по трём строкам, а не по заголовку.

## Как работает

```
Хабр ──► парсер ──► PostgreSQL ──► выжимка через YandexGPT ──► дайджест в Telegram
          ▲                                                            │
          └──────────── расписание Celery beat ────────────────────────┘
```

Три задачи Celery работают по расписанию: парсинг новых статей раз в несколько часов (интервал задаётся конфигурацией), генерация выжимок для необработанных статей и рассылка дайджестов раз в час. Разделение на три задачи, а не одна цепочка, нужно, чтобы отказ модели не блокировал сбор статей, а медленная рассылка не задерживала парсинг.

Статьи и отправки хранятся отдельно: таблица `sent_articles` помнит, что именно ушло конкретному пользователю, поэтому один и тот же материал не приходит дважды и при этом достаётся всем подписчикам темы.

## Структура

```
app/
  api/routes.py       HTTP-ручки: состояние базы, статистика, пользователи, темы
  bot/
    handlers/         обработчики по разделам: команды, темы, подписки, диагностика
    bot.py            отправка сообщений и запуск polling
  services/
    parser_service.py разбор страниц Хабра через aiohttp и BeautifulSoup
    yandex_service.py вызовы YandexGPT
    digest_service.py сборка и рассылка дайджестов
    database_service.py операции с данными
  database/           модели и подключение
  core/config.py      конфигурация
celery_app/           планировщик и задачи
migrations/           Alembic
tests/
```

## Обработка ошибок

Бот зависит от трёх внешних систем: Хабр, YandexGPT и Telegram. Любая из них может ответить ошибкой или не ответить вовсе, поэтому обработка разделена по слоям.

В сервисах ловятся конкретные типы: сетевые ошибки `aiohttp` при загрузке страниц, ошибки разбора вёрстки при изменении разметки Хабра, `SQLAlchemyError` при записи с откатом транзакции. Широкий `except Exception` остаётся только на границах — в HTTP-обработчиках, в обработчиках телеграма, в задачах Celery и в рассылке дайджестов, где падение на одном пользователе не должно прерывать рассылку остальным. Эти места отмечены в конфигурации линтера явным исключением, а не подавлены поштучно.

Наружу текст исключения не уходит: клиент получает общее сообщение, подробности со стектрейсом идут в лог.

## Запуск

Нужны Python 3.11+, PostgreSQL, Redis.

```
uv venv && source .venv/bin/activate
uv pip install ".[dev]"

cp env.example .env
```

В `.env` заполняются `TELEGRAM_BOT_TOKEN`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и строки подключения к базе и Redis.

```
alembic upgrade head
python main.py
```

Отдельно поднимаются воркер и планировщик:

```
celery -A celery_app.celery_app worker --loglevel=info
celery -A celery_app.celery_app beat --loglevel=info
```

В контейнерах: `docker compose up -d --build`. Образ собирается в два этапа, приложение работает не от root, логи по умолчанию идут в stdout — файловый лог включается переменной `LOG_FILE`.

## Проверки

```
pytest tests/
ruff check app tests main.py celery_app migrations
ruff format --check app tests main.py celery_app migrations
```

CI прогоняет линтер, проверку формата, миграции и тесты на живых PostgreSQL и Redis.

Тестами покрыты конфигурация, модели и базовые ручки API — 9 тестов. Это мало: парсер, генерация выжимок и логика рассылки не покрыты, потому что требуют заглушек для Хабра и YandexGPT. При разборе кода стоит смотреть на `app/services` — там сосредоточена вся содержательная часть.

## Ограничения

- парсер завязан на текущую вёрстку Хабра: изменится разметка — сломается разбор, поэтому ошибки разбора логируются и пропускаются, а не роняют задачу
- выжимка стоит денег: каждая статья это запрос к YandexGPT, при большом числе тем расходы растут линейно
- нет ограничения частоты обращений к Хабру, кроме интервала между запусками парсинга
- дайджест уходит всем подписчикам темы одновременно, без учёта часового пояса
- нет ретраев у задач Celery: упавшая задача ждёт следующего запуска по расписанию
- пользовательские темы добавляются свободным текстом и не модерируются
